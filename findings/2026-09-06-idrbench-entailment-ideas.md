# IDRBench：先推进的三个 idea

2026-09-06。探索结果，目的是选择下一步研究方向；以下“弱化/细化”均指模型检出的、有时间和可见历史支持的候选，不是真值或因果传输率。

## 1. 信息划分可能推迟整合，而非单纯减少信息损失（优先）

10 个任务配对，full/split 信息划分 × generic/specialist 角色分化；通信拓扑全部 full，三轮 cumulative memory。

分母是第 2、3 轮的输出 mentions。一个输出若与可见同伴的较早输出有相应的直接判决边，记一次；多条输入边不重复增加该输出的权重。同一个输出可以同时有弱化、细化等关系，列之间不互斥。表为 10 个任务的场次率均值。

| 条件 | 弱化候选输出 | 细化候选输出 |
|---|---:|---:|
| full-generic | 28.0% | 33.3% |
| full-specialist | 27.0% | 34.7% |
| split-generic | 17.7% | 20.3% |
| split-specialist-aligned | 17.5% | 18.6% |

split 下两种角色的两个方向都降低，四个比较均为 10/10 任务同向。弱化的配对差为 generic −10.3pp、specialist −9.4pp；细化为 −13.0pp、−16.1pp。这支持“跨 agent 语义关联整体减少”的候选解释，不能把较少弱化直接读成更高质量。

时间提供了进一步线索。下表按每个条件/轮次汇总 mentions，因而与上表的场次均值口径不同：

| 条件 | R2 弱化 | R3 弱化 | R2 细化 | R3 细化 |
|---|---:|---:|---:|---:|
| full-generic | 22.7% | 33.4% | 24.6% | 42.4% |
| full-specialist | 17.8% | 36.3% | 29.4% | 40.4% |
| split-generic | 6.7% | 28.0% | 8.7% | 30.2% |
| split-specialist-aligned | 8.0% | 25.2% | 9.7% | 26.1% |

**可检验解释：** 分信息局的第一轮主要用于介绍私有材料；下一轮开始吸收，第三轮才大量改写与细化。完整信息局更早进入这一步。

**最小下一步：** 使用已有 delivery，仅看上一轮新投递的内容，并按可见输入事实数归一化，检验 split 的延迟是否仍在。再区分源材料复述与提出的研究机制。cumulative memory 下 R3 有更多可见历史，当前轮次增长不能直接证明累积降级。

## 2. 二值匹配会漏掉一类有输入依据的“新输出”

9,438 个后两轮输出 mentions 中，2,109 个有可见同伴→自身的弱化候选边；其中 **1,309 个没有直接的可见同伴等价边**，占全部后两轮输出的 **13.9%**，占弱化候选输出的 **62.1%**。

这给“有向边相对于集合指标新增什么”一个可量化切入口：输出与输入并不等价，却存在更弱表述关系。仅用等价边的同伴复用通道看不到这类关系。

这里的“没有等价边”只针对已评分的 mention 对，不等于语义上绝无等价表述，也不等于该输出完全新造；它还可能来自源材料、自身历史或未召回的匹配。抽取粒度也会制造这一现象。

**最小下一步：** 对这 1,309 个输出做分层内容归类，优先看数量、适用条件、归属、研究提案与已证实结果之间的变化，寻找“二值统计相近、实际改写方向不同”的任务对。先做少量有说服力的案例，再决定是否扩展标注。

## 3. 角色的作用可能是决定改写内容，而非改写总量

specialist 相对 generic 的弱化率差：full −1.0pp，split −0.1pp；任务配对 bootstrap 区间均跨零。当前没有清楚的总量角色效应。

**候选问题：** 领域专家是否保持本领域的具体限定，却泛化另一领域的内容？综合者 C 是否更容易保留方法的连接关系、压缩原论文的性能数字？这比继续寻找“specialist 总体降低弱化”更值得试。

**最小下一步：** 按接收者 A/B/C × paper-b/paper-c 归属切分现有事件，比较本领域/跨领域的限定保留。generic 提供位置对照。split 中 C 没有原始论文，位置、信息与角色必须共同解释，不能称为星型中心效应。

## 全体清点：已完成的硬结果

目录实际含 50 个 debate；其中 40 个有 atomized + NLI store，形成完整 10×4。另 10 个 specialist-mismatched 只有 debate，本分析不纳入。

| 直接判决类型 | 候选 mention 对 |
|---|---:|
| EQUIVALENT | 7,566 |
| A_ENTAILS_B | 8,273 |
| B_ENTAILS_A | 9,773 |
| UNRELATED | 69,231 |
| 总计 | 94,843 |

单向占非无关候选对 **70.46%**；40 场均值 **70.70%**，标准差 **4.27pp**，中位数 **70.36%**，四分位区间 **67.87%–72.84%**，范围 **61.35%–82.46%**。这些是 blocker 选出的候选对的分布，不是任意事实对或全部传播的比例。

18,046 条单向判决叠上 provenance 和 delivery 后：

| 类别 | mention 对 |
|---|---:|
| 较强的同伴表述在前→较弱输出在后，且可见 | 3,251 |
| 较弱的同伴表述在前→较强输出在后，且可见 | 4,088 |
| 自身可见历史→弱化 | 1,732 |
| 自身可见历史→细化 | 2,201 |
| 同轮平行表述 | 4,642 |
| 至少一端为源材料 | 2,132 |

3,251 条同伴弱化边，按场内有序簇对去重为 2,697 对；去掉同簇两端剩 **2,530 对**。按原文本与极性去重为 3,177 对。2,567 条来自当轮新投递，684 条只来自累积历史。不能混用这些计数单位。

弱化与细化的相对量在共享阈值 0、2.64、5.28、7.92、10.56 的离线敏感性分析中方向不变，均为细化候选更多；这只说明对这段阈值范围稳定，不证明语义判断正确。也不能把两者相减当作信息量净变化。

## 测量边界，留给后续 refine

- 40 场配置一致：Qwen/Qwen3-14B，双向共用阈值 **5.28**；blocker 为 bge-base，门槛 0.62、top-k 12，union-min 0.85。实际 blocking 分数是 max(cosine, token containment)，store 中名为 blocker_cosine 的字段不能直接当纯余弦。
- 5.28 的标定文件不在本地；store 没有记录 oracle、划分或标定文件哈希。交接提供的同集拟合/评估准确率属于乐观上界。当前代码虽已支持 holdout，不能据此追认这些既有 store 使用了独立留出标定。
- 1,774 条单向判决、1,002 条 UNRELATED 判决的端点处于同一簇。主分析使用实际评分的 mention 端点，不把簇内其他成员自动扩展成有向边。涉及簇去重与上下文排除的字段是辅助诊断。
- 初步原文抽查发现真实的数值遗漏，也发现拼写变体、拆分不一致、原文保留而原子漏掉限定、不同研究活动被错判为蕴含。现阶段不把旧的“17% 误判率”移植到新事件总体；40 条固定抽样包已生成，逐条审阅尚未完成。
- 360 个 turn 中有 6 个空抽取；未局部补跑。当前生成任务没有下游质量分数，较强的断言不一定正确，较弱的断言也可能是纠正过度推断。
- 当前 MMLU-Pro 没有相同 NLI 配置的完整匹配对照。旧 generalist 缓存污染、匹配方式不同，不能拼表；本报告不声称这些模式只在不对称信息中出现。full 信息条件是当前同域对照。

## 与 DelibTrace 的实际区分

[DelibTrace 原文](https://arxiv.org/html/2606.03032v1) §3.3 已有信息不对称；§5.4 正文已有 persona 干预，D.9 给出提示细节，D.4 也讨论抽象程度。因此不能把“信息不对称”“persona”或“抽象化”单独包装成新增贡献。

可推进的区别是：**对开放生成的输出建立有方向、带时间与可见输入证据的改写关系，研究实验条件如何改变这些关系。** 其集合存活指标没有显式编码这一层关系；这不等于对方完全无法观察细节丢失。上述 idea 2 是当前可检验的增量测量，idea 1 是潜在的条件效应。

## 数据与复现

输入：`experiments/idrbench_generation_10x5_r3/*.nli.store.json` 及同名 debate/atomized。NLI store 在本次开始时均为未跟踪文件；本次不改动或提交已有数据。每个输入的 SHA-256 已保存在 summary manifest。

运行（仅标准库、离线、不调模型、不改 store）：

```bash
python3 experiments/analyze_idrbench_entailment.py
```

输出目录 `findings/data/idrbench-entailment/`：

- `summary.json`：全体统计、四条件汇总、任务配对 bootstrap/精确符号翻转结果、阈值敏感性和输入哈希。所有区间均为探索性，未校正多重比较。
- `per-trace.csv`、`per-turn.csv`：逐场、逐 agent/轮次结果。
- `peer-weakening-events.jsonl`：3,251 条候选的实际端点、原文引句、投递类型与辅助诊断。
- `sensitivity.csv`：全体 40 场在五档共享阈值下重推标签，未重新跑模型，未重建簇。
- `audit-sample.json`：每场固定随机抽一个不同文本对，带完整双方 turn；是审阅材料，不是已完成的人类 gold。
- `chain-examples.json`：直接 mention 端点连成的两步候选样例，未语义验收，不作为降级链发现报告。

本次已执行全体离线分析。优先推进 idea 1，其次用 idea 2 做方法价值展示；先不重构 pipeline、不扩跑模型。
